## Concrete findings and targeted changes

1. **High: URL import could read private network resources and forward their content to AI.** Original `src/app/api/import-url/route.ts` used unchecked `fetch(url)`, followed redirects, read unbounded response content before slicing, then sent it to the configured AI provider. The consolidated route now returns explicit HTTP 503 without reading the request or making a network call. Other three AI routes are likewise disabled in this local workspace. This avoids calling services without configuration/authority and never fabricates generated results.
2. **High: stored rich-text execution risk.** Original `src/lib/utils.ts` only excluded a case-sensitive `javascript` prefix, allowing mixed case and control-character schemes. `RichEditor.tsx:40` inserted raw saved HTML, bypassing display sanitisation. The consolidated sanitizer uses URL parsing and an explicit http/https/mailto/tel allowlist, rejects control characters and embedded credentials, and escapes fallback text during server rendering. The editor sanitises initial HTML and emitted content; clipboard paste is plain text, and HTML drops are blocked. Safe formatting and safe links still render.
3. **High workflow integrity: AI profile import overwrote user evidence.** `src/components/story/StoryPage.tsx` calls `persist(merged)` immediately following parsing (both pasted and PDF paths). Original parse prompt infers desired career direction, assigns invented numeric proficiency and requires exactly three strengths. No source provenance, review or archive accompanies the overwrite. Disabling the parse API prevents this path in the local workspace. A future integration needs reviewed proposed changes and recoverable master evidence, not automatic authoritative profile replacement.
4. **Medium: unsupported AI authority.** Original generate-email route supplies `Experienced professional` when background is absent; analyse-jd supplies the same assumption and a fit score without a defined scoring method. Original API logic is preserved only in the source archive, and removed from the active routes. Future AI should distinguish source facts, suggestions, and missing evidence; never infer personal achievements or hiring likelihood.
5. **Deployment remains unverified.** Final source's browser store reads full tables and updates by record ID, relying on Supabase row policies. A profile RLS migration is supplied, but no live policies were inspected. The older backend falls back to a public hard-coded JWT secret (`server/middleware/auth.js`); it must not be deployed or transplanted. None of this is proof of exposure in a running service.
6. **Recovery gaps in preserved final source.** Original store permanently deletes jobs and contacts. It has no versioned export/archive support and immediate profile imports; an independent data correctness pass should address these in the local workspace. Original status union also lacks closed/listing-unavailable and withdrawn semantics.

## Verification performed

Node executed the actual edited TypeScript modules: eight malicious/unsupported links rejected (mixed case script scheme, newline scheme, data, protocol-relative, relative, credential-bearing HTTPS and vbscript); four expected HTTP/HTTPS/email/phone links accepted. Server-render fallback escaped entity-bearing text. Each of the four API POST handlers returned 503 and `LOCAL_WORKSPACE_ONLY` with `Cache-Control: no-store`, even with malformed input; a fetch trap verified zero outbound calls. Browser DOM sanitisation and editor paste/keyboard rendering still require integration verification with the main app preview. No claims about production dependency security, live row policies or cloud data recovery were tested.
